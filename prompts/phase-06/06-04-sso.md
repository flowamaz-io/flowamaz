# SSO — SAML 2.0 and OIDC for Enterprise Organisations

## Context
Enterprise organisations need to authenticate via their identity provider (Okta, Azure AD,
Google Workspace, etc.). This prompt implements SSO via both SAML 2.0 and OIDC (OpenID Connect).

## Objective
SSO login flow for enterprise organisations. Org admins configure their IdP.
Users in SSO-enabled orgs are redirected to their IdP on login.

## Scope

### What to Build

**SsoConfig entity:**
```
org_sso_configs
  id                uuid pk
  org_id            uuid fk organisations (unique)
  provider          varchar (saml | oidc)
  is_active         boolean default false
  
  -- SAML fields
  idp_entity_id     text
  idp_sso_url       text
  idp_certificate   text (X.509 cert, encrypted at rest)
  sp_entity_id      text (generated: https://app.flowamaz.io/saml/{orgSlug})
  
  -- OIDC fields
  issuer_url        text
  client_id         text
  client_secret     text (encrypted at rest)
  scopes            text[] default ['openid','email','profile']
  
  created_at, updated_at, created_by
```

**ISsoService + SsoService:**

SAML:
`GetSpMetadataAsync(orgSlug, ct)` → XML metadata for SP
`InitiateSamlLoginAsync(orgSlug, returnUrl, ct)` → redirect URL to IdP
`HandleSamlCallbackAsync(samlResponse, ct)` → OrgUser (create if first time)

OIDC:
`InitiateOidcLoginAsync(orgSlug, returnUrl, ct)` → redirect URL to IdP
`HandleOidcCallbackAsync(code, state, ct)` → OrgUser

Common:
`ProvisionUserFromSsoAsync(email, orgId, claims, ct)` → OrgUser
- Find existing user by email in org
- If not found: create OrgUser with SSO-provisioned flag, assign default role (Viewer)
- If found: update name/avatar from claims
- Always: issue Flowamaz JWT (same as password login)

**API endpoints:**

`GET /api/v1/auth/sso/{orgSlug}` — check if org has SSO enabled, returns provider type
`GET /api/v1/saml/{orgSlug}/metadata` — SP metadata XML [AllowAnonymous]
`POST /api/v1/saml/{orgSlug}/acs` — SAML assertion consumer [AllowAnonymous]
`GET /api/v1/oidc/{orgSlug}/callback` — OIDC callback [AllowAnonymous]
`GET /api/v1/oidc/{orgSlug}/initiate` — start OIDC flow [AllowAnonymous]

Admin endpoints:
`GET /api/v1/organisations/{id}/sso` [OrgAdmin]
`PUT /api/v1/organisations/{id}/sso` [OrgAdmin] — configure SSO
`POST /api/v1/organisations/{id}/sso/test` [OrgAdmin] — test SSO config
`DELETE /api/v1/organisations/{id}/sso` [OrgAdmin] — disable SSO

**Login flow update:**

In LoginView.vue:
After user enters email, check /api/v1/auth/sso/{orgSlug}:
- If SSO enabled: hide password field, show "Continue with {provider}" button
- Button click: redirect to IdP initiation URL
- On return from IdP: callback handled server-side, JWT issued, redirect to dashboard

**SSO Configuration UI (Org Settings):**

`SsoSettingsView.vue` under org settings:

SAML setup wizard:
Step 1: Download SP metadata XML or copy SP Entity ID + ACS URL
Step 2: Paste IdP metadata URL or upload IdP certificate + SSO URL
Step 3: Test connection (sends test SAML request)
Step 4: Enable SSO for organisation

OIDC setup:
- Issuer URL (auto-discovers OIDC configuration)
- Client ID + Client Secret
- Test connection
- Enable

Status badge: Configured + Active | Configured but inactive | Not configured

**NuGet packages:**
- ITfoxtec.Identity.Saml2 (SAML 2.0)
- Microsoft.AspNetCore.Authentication.OpenIdConnect (OIDC — already in .NET)

**Unit tests:**
- SsoService: ProvisionUserFromSso creates new user on first SSO login
- SsoService: ProvisionUserFromSso updates existing user on subsequent login
- SsoService: SAML response with invalid signature → throws
- SsoService: OIDC callback with valid code → returns OrgUser
- LoginView: SSO org detected → password field hidden, SSO button shown

## Technical Requirements
- [ ] SAML assertions validated (signature, audience, timestamp)
- [ ] OIDC state parameter validated (CSRF protection)
- [ ] IdP certificate encrypted at rest with CREDENTIAL_MASTER_KEY
- [ ] SSO-provisioned users get Viewer role by default (configurable)
- [ ] JIT provisioning: users created on first login
- [ ] Regular password login still works for non-SSO orgs

## Acceptance Criteria
- [ ] Configure OIDC with Google → login redirects to Google → returns to Flowamaz
- [ ] New user created on first SSO login with Viewer role
- [ ] Existing user found on subsequent SSO login (no duplicate)
- [ ] Invalid SAML signature → 401
- [ ] Non-SSO org: password login works as before

## Verifier Deep Review

### Summary
Adversarial review of all Phase 8 backend changes (breakpoint wiring, redirect allowlist, workspace archive/leave isolation, CORS, EF migration, co-pilot cap, secret-logging). **Verdict: ship.** No Critical or High issues.

### Issues Found

**Low (travel forward)**
1. **Host-only redirect comparison** — `RedirectUrlPolicy.IsAllowed` compares only `Uri.Host`, not scheme/port. Off-domain redirect is impossible; an attacker already on the same host could downgrade `https→http` or change port. Optional hardening: also compare `uri.Scheme`/`uri.Port`. Minimal impact.
2. **Last-admin leave race (pre-existing)** — `LeaveWorkspaceAsync` (and the pre-existing `RemoveMemberAsync`) use a non-transactional read-then-write on `CountActiveAdminsAsync`; two admins leaving concurrently could both pass. Same pattern already shipped before Phase 8. Close with a DB constraint or serialized transaction in a future hardening pass.

**Cosmetic (no action)**
- Co-pilot per-user counter increments before the workspace-cap check, so a workspace-capped request still consumes a user slot. No security impact.

### Deep Review Assessment
Breakpoint pause/resume is deadlock-free (paused node is not persisted, so it re-enters the frontier on resume; `MarkResumed` runs before re-enqueue; `BreakpointHit→Running→Completed` is a legal transition chain; all gated on `IsDevelopment()`). Redirect allowlist resists `//evil.com`, userinfo `@`, subdomain confusion, empty-BaseUrl (fail-closed), and case tricks. Workspace archive/restore/overview are org-scoped and workspace-isolated. CORS never emits `*` and never pairs AllowCredentials with a wildcard. Migration default `"Active"` matches the enum string conversion.
